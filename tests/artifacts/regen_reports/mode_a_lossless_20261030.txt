Diagnostic only. No live codec/resource adoption or Python audio changes.
Source: current RNE Mode A image, validated before read. N64/K4/P64 and
stored int16 precision fixed. Sixteen tables per compression batch is a
transport/prediction checkpoint choice, not a transform dimension.

All 63,508 tables / 1,040,515,072 coefficients compare exactly after decoding.
Per-wave decoded/source SHA-256 also match; no lossy residuals are accepted.

Mixed predictor bound: -131070..131070 (18 signed bits); zigzag0..262140.
Differences widen before arithmetic; cumulative sums use int64 in this
Python diagnostic. Reconstruction checks int16 bounds before conversion.
No low bits, transform leaves, lanes, phase bins or pitch entries are lost.

Candidate metadata: 80-byte header + 16-byte block records; no production
format change. Whole 16-table output alone is 524,288 bytes, before predictor
and entropy scratch. No hardware decoder, DMA/prefetch, BRAM fit or realtime
qualification is claimed. Host decode measurements are offline observations.
The normative 4 MiB combined allocation / 128 MiB external capacity stay fixed.

This rejects two concrete lossless encodings, not every possible representation.
The paper's Mode A pitch-storage mechanism remains unresolved: STD-210 3.1
is pitch-dependent; RAM-SUBSYSTEMS 3.2 budgets per waveform without a pitch
axis. Clarification is pending; no silent Mode B or nominal-anchor substitution.
